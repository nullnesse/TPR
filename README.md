# Решение в коде

> `solver_core.py` — единственный источник формул; `solver.py` — совместимый вход и CLI. Числа для доклада берутся из `results.json`. По решению пользователя от 27.10.2026 ожидаемая полезность исключена из презентации, демо и речи; справочные функции utility/CE и прежние поля JSON сохранены для совместимости API и не являются методом текущего доклада.

## Запуск

```bash
# Полный отчёт и прежний results.json
python3 Задачи/Решение/solver.py

# Компактный режим API: методы доклада плюс совместимые внутренние поля
python3 Задачи/Решение/solver.py --scope core --format text
python3 Задачи/Решение/solver.py --scope core --discount 20 --rho 2 --lambda 0
python3 Задачи/Решение/solver.py --scope core --format json --runs 100000

# Явная запись компактного результата; без --output файл не создаётся
python3 Задачи/Решение/solver.py --scope core --format json --output results_core.json
```

Требования: Python 3.10+, только стандартная библиотека (без numpy/pandas).

## Структура

| Файл | Роль |
|---|---|
| `solver_core.py` | `Model`, EMV, EOL, риск/mean–SD, чувствительность и Монте-Карло; utility/CE сохранены как совместимый справочный API |
| `solver_extras.py` | Справочные расширения: дерево, критерии, EVPI/EVSI, Байес, дробление |
| `solver.py` | Совместимый фасад, полный JSON, отчёт и CLI |
| `results.json` | Полный исторический эталон чисел |
| `test_solver.py` | 34 прежних теста совместимости |
| `test_solver_core.py` | Тесты чистого ядра |
| `test_solver_cli.py` | Тесты CLI, config и отсутствия скрытой записи |

Полный режим:

1. проверяет корректность вероятностей;
2. считает EMV и EOL;
3. считает риск (дисперсию, пары исходов);
4. сохраняет справочные поля utility/CE в полном legacy JSON для совместимости;
5. считает пороги чувствительности;
6. запускает Монте-Карло (100 000 партий, seed 42);
7. добавляет справочные блоки: дерево, критерии, EVPI/EVSI, вероятности/Байес, дробление;
8. печатает отчёт и сохраняет `results.json`.

Компактный режим `--scope core` не запускает симуляцию в текстовом выводе и не перезаписывает `results.json` без `--output`.

## Что внутри `results.json`

| Ключ | Содержание |
|---|---|
| `model` | Входные параметры |
| `emv` | Затраты, ожидания, лучший поставщик, экономия; стандартная EOL и отдельные превышения над лучшим средним |
| `tree` | Значения узлов дерева — справочно; в презентацию и демо не входит (дерево дублирует EMV) |
| `criteria` | EMV, Вальд, minimin, Лаплас, Гурвиц; `savage` для вспомогательной матрицы, `savage_joint` для всех пар |
| `risk` | Средние, дисперсии, $\sigma$, распределение разницы, $P(A<B)$ |
| `probability` | Биномиальная смесь (дисперсия); `bayes` — биномиальное обновление, `bayes_finite` — точное гипергеометрическое |
| `utility` | Справочные совместимые поля utility/CE; не входят в текущий доклад |
| `evpi` | После выбора; об A/B до выбора при независимости; об обеих партиях при независимости и комонотонной связке |
| `evsi` | Ценность выборки для $n=10..200$ |
| `sensitivity` | Пороги по скидке, ремонту, качеству B |
| `split` | Дополнительная модель дробления: ожидание и риск при независимости и комонотонной связке |
| `simulation` | Монте-Карло: средние и частота |

## Ключевые формулы

Ожидаемый ремонт:

$$\mathbb{E}[R_i]=\sum_s p_i(s)\,c\,N\,r_s.$$

Ожидаемые затраты:

$$\mathbb{E}[C_A]=P_A+\mathbb{E}[R_A],\qquad
\mathbb{E}[C_B]=P_A-\Delta+\mathbb{E}[R_B].$$

Порог скидки:

$$\Delta^*=\mathbb{E}[R_B]-\mathbb{E}[R_A].$$

Порог стоимости ремонта:

$$c^*=\frac{\Delta}{N(\mathbb{E}[r_B]-\mathbb{E}[r_A])}.$$

Порог качества B:

$$\mathbb{E}[r_B]^*=\mathbb{E}[r_A]+\frac{\Delta}{Nc}.$$

Стандартная ожидаемая упущенная выгода (EOL) при независимости партий:

$$\mathrm{EOL}_i=\mathbb E[C_i-\min_j C_j]=\mathbb E[C_i]-\mathbb E[\min_j C_j].$$

В базовом сценарии EOL равны 24,65/17,65 тыс. руб. Числа 7/0 сохранены отдельно в `emv.excess_over_best_mean`; минимальная EOL равна EVPI. Для сопоставления исходов альтернатив нужно совместное распределение, которого нет в условии.

EVPI:

$$\mathrm{EVPI}=\min_i\mathbb{E}[C_i]-\mathbb{E}\left[\min_i C_i(s)\right].$$

EVSI:

$$\mathrm{EVSI}=\min_i\mathbb{E}[C_i]-\mathbb{E}_k\left[\min_i\mathbb{E}[C_i\mid k]\right].$$

Справочная формула совместимого API (не метод текущего доклада): экспоненциальный денежный эквивалент затрат:

$$CE=\rho\ln\mathbb{E}\left[e^{C/\rho}\right].$$

## Смысл параметров и дополнительных сценариев

- `price_a=0` — отсчёт относительно неизвестной цены A, а не утверждение о бесплатной закупке. При ненулевой `price_a` все затраты и CE включают цену; EOL, EVPI, EVSI и выбор не меняются от общего сдвига. Байес при `price_a=100`, $n=50$, $k=1$ даёт 172,02/163,00 тыс. руб. и выбирает B.
- Скидка `discount` фиксирована на партию: при `N=20000` средние относительно цены A — 140/163 тыс. руб., выбор A. Пропорциональная скидка требует отдельного изменения `discount`.
- Комонотонная связка сохраняет оба исходных распределения. Полная информация об обеих партиях даёт ожидаемые затраты $P_A+55{,}2$ тыс. руб. и EVPI 7,8 тыс. руб. Ключи: `both_comonotonic`, `e_perfect_comonotonic`, `comonotonic_joint`. Это максимальная положительная зависимость, а не корреляция +1. Старый ключ `both_perfectly_correlated` удалён.
- Сэвидж на всех девяти парах имеет оценки 137/63 тыс. руб.; вспомогательная матрица одинакового брака — 37/0 тыс. руб.
- `risk.cv` использует полные затраты при заданной `price_a`; `cv_relative_to_price_a` использует затраты после вычитания цены A. Значения 47,4 %/61,5 % относятся к последнему варианту. При неположительном среднем CV равен `null`.
- В `utility.budget` поле `budget` — остаток относительно цены A; `absolute_budget=price_a+budget`. Например, остаток 60 означает полный лимит $P_A+60$ тыс. руб.
- Mean–SD минимизирует самостоятельную оценку $J=\mathbb E[C]+\lambda\sigma$. Legacy поля utility/CE остаются ради совместимости и не являются частью презентации, демо или речи.
- `bayes` и EVSI используют биномиальное приближение. При выборке без возвращения из партии с ровно $Nr$ дефектами точное правдоподобие гипергеометрическое; `bayes_finite` даёт 61,2205 тыс. руб. ремонта A при $n=50$, $k=0$ против 61,2369 тыс. руб. по биномиальному приближению. Если $Nr$ не целое или $n>N$, `bayes_finite` равен `null`: такая конечная модель не задана. Невозможное наблюдение отклоняется понятным `ValueError`.
- В EVSI(обе) $n$ — размер выборки у **каждого** поставщика; стоимость двух проверок учитывается отдельно и вдвое больше при одинаковой цене за деталь.
- Дробление требует дополнительных допущений: разрешены подзаказы, цены и скидка пропорциональны долям, распределение качества не зависит от объёма. `sd_comonotonic` заменяет прежнюю недостижимую кривую корреляции +1.
- Нулевые вероятности и нулевая стоимость ремонта допустимы; неопределённые пороги выводятся как `null`. Доли вне $[0,1]$, отрицательные или неконечные параметры отклоняются. JSON не содержит NaN/Infinity.

## Как менять параметры

```python
from solver_core import Model, emv, eol, mean_sd, utility

m = Model(c=0.8, discount=20)
print(emv(m)["expected_costs"])
print(eol(m)["expected_regret"])
print(mean_sd(m, 2)["choice"])
print(utility(m, 100)["choice"])  # справочный legacy API; не метод доклада
```

Полный исторический JSON собирается через `solver.build_results`, а параметры можно менять из CLI:

```bash
python3 Задачи/Решение/solver.py --scope core --repair-cost 0,8 --discount 20
python3 Задачи/Решение/solver.py --scope core --n 20000 --p-b 0.2 0.4 0.4
```

## Ограничения

- Модель считает, что доля брака — свойство всей партии (три уровня), а не отдельной детали.
- Все дефекты обнаруживаются и ремонтируются.
- Нет других затрат (логистика, простои, репутация).
- Вероятности считаются известными и стабильными. Нейтральность к риску — предположение основного ответа; регулярность закупок не задана. Если закупки повторяются с независимыми партиями, применим закон больших чисел.
- Монте-Карло — приближённый метод; при 100 000 прогонов ошибка среднего порядка 0,1–0,2 тыс. руб.

## Воспроизводимость

- Симуляция использует `random.Random(seed)`; при одном seed результат одинаков.
- При фиксированном seed симуляция также детерминирована; при другом seed её оценки могут отличаться.
- JSON не содержит времени и случайных идентификаторов.
